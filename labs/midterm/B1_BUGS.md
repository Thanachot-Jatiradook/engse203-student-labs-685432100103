# B1 · บันทึกการแก้บั๊ก (กรอกให้ครบทั้ง 6 จุด)

> แต่ละบั๊กให้เขียน 4 อย่าง: ไฟล์ · บรรทัด · สาเหตุ (ทำไมทำงานผิด) · แก้อย่างไร
> เขียนด้วยคำของตัวเอง — จุดนี้จะถูกถามใน oral

## บั๊กที่ 1 — อาการ: Console เตือนสีเหลืองเรื่องรายการ
- ไฟล์/บรรทัด: RequestList.jsx (บรรทัดที่ 9)
- สาเหตุ: ในฟังก์ชัน RequestList มีการใช้ .map() เพื่อวนลูปสร้างคอมโพเนนต์ <RequestCard> แต่ไม่ได้ใส่ key prop ซึ่ง React บังคับให้ต้องมีเพื่อใช้ติดตามการเปลี่ยนแปลงของแต่ละ component ย่อยใน list
- แก้อย่างไร: ให้เพิ่ม key={request.id} เข้าไปใน <RequestCard>

## บั๊กที่ 2 — อาการ: ตัวเลข "รอดำเนินการ" ในแผงสรุปไม่ตรงกับที่เห็น
- ไฟล์/บรรทัด: DashboardPage.jsx (บรรทัดที่ 47)
- สาเหตุ: ในการคำนวณ summary (บรรทัดที่ 47) มีการนับจำนวน pending ผิดพลาด โดยไปกรองด้วยสถานะ 'completed' ทำให้มันไปแสดงตัวเลขเดียวกับของ "เสร็จสิ้น"
- แก้อย่างไร: เปลี่ยนเงื่อนไขการนับสถานะ pending ให้ถูกต้องเป็น 'pending'

## บั๊กที่ 3 — อาการ: กดตัวกรอง "รอดำเนินการ" แล้วได้รายการที่ไม่ใช่
- ไฟล์/บรรทัด: DashboardPage.jsx (บรรทัดที่ 55)
- สาเหตุ: โค้ดส่วนที่ทำการกรองข้อมูล (บรรทัดที่ 55) เขียนเงื่อนไขผิดเป็น !== (ไม่เท่ากับ) ทำให้แทนที่มันจะดึงข้อมูลสถานะที่เราเลือก มันกลับกรองเอาเฉพาะตัวที่เรา ไม่ได้เลือก มาแสดงแทน
- แก้อย่างไร: เปลี่ยนตัวดำเนินการจากการเช็กว่า "ไม่เท่ากับ" ให้เป็น "เท่ากับ" (ตรวจสอบว่าตรงกับ filter หรือไม่)

## บั๊กที่ 4 — อาการ: เปลี่ยน URL จาก REQ-001 เป็น REQ-002 แล้วข้อมูลไม่เปลี่ยน
- ไฟล์/บรรทัด: RequestDetailPage.jsx
- สาเหตุ: ใน useEffect (บรรทัดที่ 28) มีการใส่ dependency array (อาร์เรย์ที่คอยดักจับความเปลี่ยนแปลง) ไว้แค่ [reloadKey] แต่ไม่ได้ใส่ requestId เข้าไปด้วย ทำให้พอกดเปลี่ยน URL ตัว React Router จะเปลี่ยนค่า requestId ให้ใหม่ก็จริง แต่เนื่องจากไม่มีใน dependency array ตัว useEffect เลยไม่ทำงานใหม่ ข้อมูลจึงยังเป็นของ ID เดิม
- แก้อย่างไร: เพิ่ม requestId เข้าไปใน dependency array ของ useEffect เพื่อให้มันดึงข้อมูลใหม่ทุกครั้งที่ค่า ID เปลี่ยนไป

## บั๊กที่ 5 — อาการ: กด "ลบ" แล้วรายการยังอยู่ ต้องรีเฟรชถึงหาย
- ไฟล์/บรรทัด: DashboardPage.jsx
- สาเหตุ: ในฟังก์ชัน handleDelete (บรรทัดที่ 65) หลังจากเรียกคำสั่งลบข้อมูลสำเร็จแล้ว ฟังก์ชันจะอัปเดต state ด้วยคำสั่ง setRequests แต่ดันทิ้งตัวแปรเก่า requests ใส่เข้าไปแทนที่จะเป็นตัวแปรใหม่ nextRequests ที่ได้กลับมาจากการลบ ทำให้หน้าจอไม่อัปเดตข้อมูลล่าสุด
- แก้อย่างไร: เปลี่ยนตัวแปรใน setRequests ให้เป็น nextRequests

## บั๊กที่ 6 — อาการ: กด "Reset Demo Data" แล้วหน้าพัง/ว่างเปล่า
- ไฟล์/บรรทัด: DashboardPage.jsx
- สาเหตุ: ในฟังก์ชัน handleReset (บรรทัดที่ 75) มีการเรียกใช้ resetRequests() ซึ่งเป็นฟังก์ชันแบบ asynchronous (คืนค่าเป็น Promise) แต่ไม่ได้ใส่ await ดักรอไว้ก่อน ทำให้ setRequests ได้รับค่าเป็น object ของ Promise ไปแทนที่จะเป็น array ของข้อมูลจริง ๆ หน้าจอเลยพังเพราะมันเอาไป .map หรือกรองไม่ได้
- แก้อย่างไร:  เติมคำว่า await ไว้หน้า resetRequests() เพื่อรอให้ได้ข้อมูลจริงกลับมาก่อนแล้วค่อยเซ็ตลง state
